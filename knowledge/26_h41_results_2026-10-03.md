## 2. Why this pass is not an emission fluke

- **Ranking improved, not just the draw.** Footprint holdout AUC (mean over the 8 cells): control 0.8037 →
  `A1` 0.8159, `A4` 0.8159, `A2` 0.8138, `A3` 0.8154. A +0.012 AUC step is a property of the scored field,
  not of where the top-K cut happened to fall.
- **Emission was not allowed to buy the gain.** Budgets stay inside 0.977–1.013× control in all 40 cells
  (the frozen band is 0.75–1.25), so the gain is dot *placement* at a fixed number of dots.
- **The information is genuinely new relative to the catalogue block.** Spearman correlation of `H41_OFF`
  (fold NW, draw 28, all 5,167,373 footprint pixels) with the frozen E-family columns: `E_dist` −0.266,
  `E_dens5` +0.231, `E_dens20` +0.269, `E_dens50` +0.224, `E_cos2` −0.006, `E_sin2` +0.008, `E_coh20`
  +0.035, and with the H27 scarp composite +0.032. Nothing is orthogonal-by-construction, but |ρ| ≤ 0.27
  against every existing channel means the model is not re-reading the catalogue through a new pipe.
- **The H31 failure mode is provably absent.** The pre-declared degeneracy guard (nonzero on ≥ 0.2 % of
  footprint pixels) passed by 17–150×: `H41_SUPP` 30.13 %, `H41_OFF` 16.19–17.61 % across the 8 cells,
  `H41_CORR` 3.34–4.07 %, `H41_OFF_SCARP` 5.38–6.00 %, `H41_PURITY` 19.55–21.29 %. Every cell's
  `nonzero_fraction` is in `cells_screen.jsonl` under `h41_diag`.

## 3. The counter-evidence, in the same document

- **The second proxy moves the other way.** Against the SGMC off-catalogue fault class, every arm *loses*:
  mean paired change −0.0011 (`A1`), −0.0009 (`A2`), −0.0017 (`A3`), −0.0023 (`A4`), with 1–2 of 4 folds
  positive. This is the registered proxy conflict (`IR-29-PROXY-CONFLICT`), now reproduced with a feature
  that helps the primary target. The two proxies disagree about *this* mechanism in particular: an INGENIOUS
  centroid that is off the supplied catalogue tends to sit near SGMC-mapped faults that the *labels* omit,
  so the same pixels that teach the primary proxy "unlabelled young fault" tell the SGMC proxy "wrong place".
  A slot decision must not be made on the primary proxy alone.
- **Input ceiling is what we declared before the run.** The pinned mirror carries one centroid per trace, no
  polyline: 1,126 rows read, 376 in-footprint, 160–178 of them off-catalogue per draw, 0 dropped out of
  grid, 0 unparsable, 1 outside the frozen age-bin table (the truncated `"<130,00"` bin, fallback weight,
  `IR-29-QFAULTS-RECENCY-BIN`), max slip rate 4.5 mm/yr, `support_scale` 1.024998. Gains therefore arrive
  through km-scale prior shaping. Anyone tempted to claim dot-level placement from this file is over-reading it.
- **`above_holdout_best` in the analyzer is a trap, not a result.** The report prints `true` for every arm
  because it compares *this screen's* mean DTI (0.1530) against `holdout_best` 0.14479 — which was measured
  on the H34 protocol's own draws 20/21. This screen's control sits at 0.14635 on the same cells, i.e. also
  "above" it. The comparison is only meaningful *within* one cell set, so the field is read as "the screen's
  control baseline is 0.14635 on draws 28/29" and nothing more. Slot eligibility still requires a candidate
  scored on the same protocol as the record it must beat (§5).

## 6. Disclosed process defects (all found by review, none gate-affecting)

1. **Smoke overlap.** Before the formal run, one screen cell (fold NW, draw 28, all five arms) had already
   been computed once as an end-to-end smoke of the new runner. The formal run recomputed it and produced
   byte-identical DTIs (`C0=0.1723 A1=0.1788 A2=0.1764 A3=0.1814 A4=0.1848`), which doubles as a
   determinism check. No parameter, arm, gate or draw was changed between the two. `IR-29-H41-SMOKE-OVERLAP`;
   future smokes must use a draw outside the frozen set.
2. **Analyzer guard check inverted** (`IR-29-H41-ANALYZER-GUARD-BUG`): it flagged every clean run with
   "viability_guard passed flag inconsistent with its problem list". Fixed after the screen finished, in the
   consistency check only (no gate, threshold or cell value), and the corrected analyzer reports
   `problems: none`. The un-fixed version's complaint is what led to reading the guard records by hand and
   confirming them in `cells_screen.jsonl`.
3. **Five mis-stated sentences in the frozen preregistration** (`IR-29-H41-PREREG-STAT-CORRECTIONS`):
   median in-footprint clipped trace length is 9.99 km, not 7.1 km (p25 3.64, p75 21.69, max 200.1 km);
   `slip_rate` spans 0.0001–4.5 mm/yr, not 1.47e-5–4.5 (the smaller figure is a derived weight, not a rate);
   the "16.0 % of the whole grid" sentence describes the `H41_OFF` footprint fraction (16.2 %), while
   `H41_SUPP` is 30.13 % of footprint / 13.17 % of grid pixels at the guard threshold and the raw centroid
   raster is 0.0031 %; the reused `_trace_grids` operator is a single σ=2 px Gaussian + `np.gradient` + a
   σ=2 px-smoothed normalized structure tensor with **no** 0.5 px pre-smoothing, **no** 3×3 window and **no**
   percentile clip; and `support_scale` is the 99.9th percentile over all nonzero grid pixels rather than
   "in-footprint only" (1.024998 vs 1.000440, a 2.45 % constant divisor applied identically to all five
   columns, which cannot change any tree split or cross-column ordering). The code is the authority for what
   ran; `design_screen.json` pins it.
4. **A fabricated external source, corrected the same day** (`IR-29-UNVERIFIED-HOSTS`): the v4 slate
   initially named a Nevada "NV-DGGS" GitHub organization and two portal hostnames for H47. `api.github.com`
   (the only host reachable from this sandbox) returns 404 for `users/NV-DGGS` and 0 search hits for
   "geologic map Nevada survey"; `UGS-GIO`/`UGS-GIS` (Utah) do exist. H47 is now recorded as **blocked**, with
   no unverified hostname asserted anywhere.
5. **Dangling rule inside the frozen file** (`IR-29-H41-DANGLING-CANDIDATE-SCORE-RULE`): `knowledge/24` §4 G2
   refers to "the pre-registered candidate-score step of `knowledge/23` (candidate score = 1.5 × screen mean
   ΔDTI, hard cap +0.030)". There is no `knowledge/23`, and no such formula or cap exists anywhere in this
   repository. The policy actually in force is the one stated in the same section and in
   `registry/status_feed.json`: a weekly slot is considered only if the candidate beats the
   same-protocol catalogue-hidden best on a real candidate build and passes the exact-file audit — for the
   record, that bar is `holdout_best = 0.14479018210246675` measured on the H34 protocol, so a candidate from
   this screen must be re-scored on that protocol before it can be compared at all.
