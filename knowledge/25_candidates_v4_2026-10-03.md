Supersedes nothing: `knowledge/20_candidates_v3_2026-10-03.md` stays as the record of what was proposed
then. H41 was promoted out of this slate into a frozen screen (`knowledge/24`); the remaining five are
recorded here with the four required fields each (layers, expected signature, why off-catalogue, difference

Ranking rule declared before any of them is run: **cost** = new-data dependency × implementation risk × the
number of weekly-slot-eligible cells it implies; **expected gain** = the size of the physical mechanism ×
how much of it the existing 64-column static block + 7 E + 7 extra + 3 H27 columns already capture. The
family base rate is brutal and is the prior: five consecutive feature-adding screens have returned
−0.014 … +0.006 on the frozen ±0.005 gate (`knowledge/18`, `knowledge/21`), i.e. **a passed gate, not a
positive mean, is the only thing that has ever justified a slot**, and none has passed.

## H43 — drainage-network organization: stream-power residual and knickpoint excess  ⟶ **top candidate to build next**

- **Layers:** `det_elev` (already cached, 100 m grid, −590…+1470 m, continuous), `det_elev_slope`, D8
  contributing area, and the existing catalogue for the "channel not yet on a mapped fault" mask.
- **Expected signature:** in extending basins the fault trace *is* the line along which water escapes;
  stream power `Ω = ρ g Q S` (≈ `A^m S`, m≈0.5–1) computed on the grid peaks in the channel and drops off
  bank-to-bank, so a **ridge of Ω along the range-front trend** is a 200–500 m-wide corridor of exactly the
  shape the emission stage needs. A knickpoint is an *excess* of local steepness over the smooth
  `S ∝ A^(−θ)` profile (θ from a log-log robust fit per basin, ~0.3–0.9 in the Sierra Nevada/Great Basin
  literature); knickpoint density along a front co-locates with active uplift on that front.
- **Why off-catalogue:** the supplied catalogue contains point and edge features only (labels, wells,
  springs, seismicity density `deq_n100a15`/`ieq_n100a15`, conductance, gravity/magnetism). There is no
  hydrologic routing anywhere in the repository: `grep -rniE "flow_accum|d8|knickpoint|stream_power"` over
  `src/ scripts/ tests/` returns nothing (session-4 check). Drainage integration is a *network* property:
  it needs the entire upslope catchment, so no local window of the existing 100 m bands can be re-weighted
  to produce it — which is also why the boosted trees never found it in the slope/TPPI/Laplacian blocks.
- **Difference from repo work:** H27/H30 filtered the scarp *within* the catalogue geometry; H31/H40
  filtered potential-field ridges (persistence-with-height, three negative verdicts); H35 built interaction
  zones between catalogue segments. H43 is the first candidate to use the **topographic boundary condition**
  (which way the ground drains) as an independent structural probe, and the first to produce a *linear*
  feature that is not derived from the magnetic or gravity field.
- **Cost / rank justification:** zero new data (buildable in-sandbox from the cached band; D8 over
  3,730 × 3,292 is a single priority-flood pass, minutes), zero datum/reprojection risk, moderate
  implementation risk (flow routing bugs are silent, so the guard is a printed catchment-area histogram and
  a synthetic-slope unit test whose accumulation is analytic). Expected gain: the physical coupling is
  first-order (drainage follows structure, structure is what is labelled) and the feature is dense
  (nonzero over most of the basin fraction), which is the exact failure mode that killed H31. Cheapest
  credible gain in the slate, hence rank 2 behind the already-running H41.
- **Known risks (stated up front):** 100 m DEM is coarse for knickpoint detection; pediment/volcanic-cover
  pixels have no meaningful channels, so the field must be delivered *with* a validity mask column; and
  drainage anomalies are quasi-static, so any gain must show up through ranking, not through new mass.

## H44 — spring-to-gauge discharge chain (hydrologic continuity of the fluid pathway)

- **Layers:** `data/external/gdr_wellspring_in_footprint.csv` (already mirrored, 2.1 MB, includes max
  temperature and chemistry) for thermal springs; USGS NWIS daily discharge for the gauges whose basins
  touch the footprint; basin outlets derived from H43's flow routing.
- **Expected signature:** a thermal spring whose *downstream* gauge records an anomalously large dry-season
  base flow implies sustained deep circulation along a connected pathway; the pathway is a line from spring
  to gauge, and segments of it that cross range fronts are the favoured locus for the labelled structure.
  Feature = distance to the spring→gauge chain, weighted by log(dry-season Q).
- **Why off-catalogue:** the catalogue's spring/well block (`D_gdr_dist_hot`, `D_gdr_kde2km`, `D_gdr_tmax5km`,
  `D_gdr_quartz5km`, built in `src/gemsdoe/features.py:185` from the same CSV) encodes *where heat is* and
  *how many holes are nearby*. It contains no fluvial connectivity: a spring 8 km downstream of another
  spring on the same fault is indistinguishable from two isolated springs.
- **Difference from repo work:** H37 tested young-fault density *around* springs (a spatial co-location
  test, `knowledge/15`). H44 tests the *ordering* of springs and gauges along a drainage path — a directed,
  hydrologically-routed quantity, not a density.
- **Cost:** medium-high — needs an NWIS download (owner-side, blocked in-sandbox), gauge-to-basin
  attribution, and a defensible dry-season statistic. Expected gain is smaller than H43's because it is
  downstream of the same physics at lower resolution. Rank 3.

## H45 — seismicity *strand* fitting rather than seismicity density

- **Layers:** USGS ComCat (`earthquake.usgs.gov/fdsnws/event/1/query`, API documented as public and free)
  for M≥1.5 events, ~30 yr, within 0.6° of the footprint; then structure-tensor/DBSCAN strand fitting to the
  hypocentre cloud, and distance-to-nearest-strand as the feature.
- **Expected signature:** hypocentres are not a Poisson cloud; they line up on a handful of strands, and a
  strand that is *not* in the supplied catalogue is a live structure the organizers' label class ("newly
  mapped geometry") may contain. Distance-to-strand has a ~1–2 km corridor of the right sign and
  orientation; distance-to-density-centroid (what `deq_n100a15`/`ieq_n100a15` provide) does not.
- **Why off-catalogue:** the catalogue's two seismicity bands are 100 m-grid **counts in a 100-by-150 km
  bin** (per `knowledge/03` band list) — order-of-magnitude coarser than the strand geometry, and
  directionless.
- **Difference from repo work:** the family-C use of seismicity in this repository is density only;
  `deq_n100a15`/`ieq_n100a15` sit in the frozen static block and were never tested as *oriented* fields.
- **Cost:** medium. Needs a download (owner-side), hypocentre-quality filtering (depth errors of ±3–5 km in
  this region smear a 500 m corridor), and a strand-fitting routine with honest uncertainty. Expected gain
  is plausible but the corridor is much wider than the dot spacing, so it mostly re-weights the prior.
  Rank 4 — and explicitly gated on H43, since both are "structure from an unmodelled field" bets.

## H46 — 1-m LiDAR scarp template along GeoDAWN flight lines

- **Layers:** GeoDAWN LiDAR/photogrammetry (USGS GDR 1391's companion acquisition; DOI
  `10.5066/P93LGLVQ`) — the only 1-m-resolution surface in the region, on flight corridors that cross
  several range fronts inside the footprint.
- **Expected signature:** a matched template (crest–trough pair, 1–3 m throw, 10–40 m width) gives a
  sharpness amplitude that is 1–2 orders of magnitude better resolved than anything derivable at 100 m;
  a *detected* scarp with no catalogue trace is a direct geometric prediction.
- **Why off-catalogue:** the supplied raster family is 100 m and the derived bands were computed at that
  resolution, so sub-grid scarp geometry simply does not exist in them.
- **Difference from repo work:** H27 built tip/scarp products from the 100 m field (`ctx.h27_scarp`,
  `crest/trough` in the static block); `knowledge/22` records that the raw point-cloud route was considered
  and **deferred because of cost**, not because it was falsified. This is that deferred item, costed.
- **Cost:** high and honestly so: a multi-GB owner-side download, a flight-line mosaic, registration checks,
  and a template detector with a false-alarm study; coverage is **corridor-limited**, so only a few tens of
  km of front can be tested, which caps the DTI contribution to well under the +0.005 gate on a per-cell
  basis. Rank 5. Kept on the slate because it is the only candidate that could change the *geometric*
  precision of dots rather than the prior.

## H47 — geological-map unit-boundary adjacency (lithologic contact, not the fault raster)

- **Layers:** Nevada Division of Geological Survey / Utah open GIS geologic-map polygons (state 1:250k
  sheets; free and official) restricted to the footprint; feature = distance to the nearest *unit contact*,
  plus a per-unit "is this boundary a fault contact" flag from the map's own attribute field where present.
- **Expected signature:** in these ranges the mapped contacts of Paleozoic metavolcanics against Cenozoic
  cover are frequently fault contacts, so a contact that is off-catalogue is a structure the label class
  wants, with a corridor width set by the mapping scale (~1:250k → km-scale, honest about being coarse).
- **Why off-catalogue:** `data/external/derived_sgmc_faults_100m_u8.tif` is only the **fault** subset of the
  State Map Model (198 KB, already the second proxy in every screen); the *unit polygons and their
  contacts* — the part of the SGMC that would carry lithology-adjacency — have never been touched, and no
  unit-boundary field appears in the static block.
- **Difference from repo work:** the repository uses SGMC faults as a truth-like proxy for off-catalogue
  faulting, never the map-unit geometry as a predictor; the geology→geothermal argument here is different
  too (permeable-vs-seal juxtaposition across a contact is a fluid-pathway argument, not a strain argument).
- **Cost:** medium-high (owner-side download of a large shapefile package, projection work, plus the
  real risk that the 1:250k contact geometry is too coarse to move a 100 m grid dot). Rank 6.
- **Obtainability, verified as far as this sandbox allows:** the only reachable host is `api.github.com`,
  and a query against it shows the Utah Geological Survey does publish GIS work on GitHub
  (`UGS-GIO/ugs-map-viewer`, `UGS-GIS/*`), while a Nevada Division of Geological Survey organization does
  **not** exist there (`users/NV-DGGS` → 404; repository search `geologic map Nevada survey` → 0 hits).
  So the state-map polygons are **not** shown to be obtainable from a fetchable endpoint: H47 is blocked
  until the owner opens the surveys' own portals directly — no portal hostname for either survey is
  verified in this repository, because `*.unr.edu`/`*.utah.gov` hosts are not reachable from the sandbox
  and a guessed hostname is not evidence of anything. A Nevada GitHub handle and a Nevada portal hostname
  were briefly written into this slate during session 4; both were unverified and were removed the same
  day (see `registry/sources.json`, id `state-geologic-maps`, and IR-29-UNVERIFIED-HOSTS).

## What this slate deliberately does *not* contain

- **No fourth worming/persistence retry.** Hornby-Boschetti-Horowitz multi-scale "worming" with
  persistence-with-height has now been screened three times in this repository against the frozen gate —
  corrected H29 five arms (`knowledge/17`), the sparse-feature H31 failure (`knowledge/16`), and the dense
  rebuild H40 (`knowledge/21`, +0.0005 / +0.0056) — and it has failed all three. Repeating it would be
  silent fishing, not science; the deliverable is the recorded verdict.
- **No "seismicity density" candidate.** Family C already carries `deq_n100a15`/`ieq_n100a15` in the frozen
  static block, so only the *strand* formulation (H45) is new.
- **No re-emission tuning.** The τ rule and the emission budget are near a local optimum for the current
  habitat (`knowledge/07`, `knowledge/13`); gains must come from a better habitat, which is why H43 ranks
  above H44-H47.

±0.005 gate with all four folds positive in every draw. That is the same policy that held for H34/H35/H40,
and it is the reason five screened ideas have produced zero submissions.
