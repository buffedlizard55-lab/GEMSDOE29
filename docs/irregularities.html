Items below include owner-mirror provenance, ambiguous labels/bands, unverified score reports, holdout limitations, and blocked external data. Each carries an impact and a mitigation.

IR-DATA-01 · high

Owner-mirrored competition rasters are not organizer-authenticated

Finding: The training-feature stack, labels, existing-fault raster, and sample template are restored from hash-pinned public owner-repository mirrors because the sandbox has no organizer login. SHA-256 pins prove integrity relative to the recorded owner revision, not that the bytes are identical to the organizer download.

Impact: Every data-backed result and artifact is conditional on the mirrored bytes. Do not claim organizer authenticity or official acceptance.

Status

open; disclosed

Mitigation: Record manifest revision, hashes, byte counts and restore receipt; link to the official data page for manual verification; keep all caches outside Git.

IR-TEMPLATE-01 · high

Sample-submission mirror is not an all-zero prediction inside its footprint

Finding: On the restored, SHA-256-pinned owner-mirror template, 60,988 finite pixels equal 1 inside the 5,167,373-pixel footprint, matching the label positive count. The official problem page calls its sample a total-fault-absence example; this local template instead contains label-like ones and is not organizer-authenticated.

Impact: Never copy template pixel values as predictions. Use only its profile and finite-pixel mask to derive grid/footprint; generate all in-footprint predictions explicitly.

Status

confirmed on restored owner-mirror bytes; template used only for grid/footprint

Mitigation: The local writer constructs a separate prediction array and checks every footprint pixel; a fresh format receipt is required for any artifact.

IR-BAND-TC-01 · medium

Ambiguous training band `tc` metadata

Finding: The owner-mirror stack's embedded description is reported to call `tc` a magnetic tilt/curvature derivative, while the predecessor reports its values correlate at Spearman 0.9999 with the USGS GeoDAWN total-count radiometric raster. The H31 repository groups it with thermal/geochemical features based on that prior internal analysis; this correlation is not a new GEMSDOE29 result.

Impact: Family D assignment is a working interpretation, not an organizer-verified semantic label. Results using family D inherit this caveat.

Status

interpretation inherited; not independently recomputed in GEMSDOE29

Mitigation: Retain the band name, document the interpretation, do not relabel the source raster, and recheck the correlation only from permitted, verified inputs.

IR-HOLDOUT-01 · high

Component-hide spatial holdout is only a catalogue-gap proxy

Finding: The hidden holdout traces are components of the existing catalogue, not the organizer's newly expert-labelled faults. The local protocol excludes visible catalogue pixels from its proxy score, but the official problem page does not fully specify those optional mask semantics.

Impact: Spatial DTI cannot be called a competition score or assumed to predict public/private leaderboard performance. Four quadrants are the spatial replication units; draws are repeated hides.

Status

disclosed design limitation

Mitigation: Use same-run paired controls, fresh confirmation, raw-cell hashes and explicit proxy language; never use a weekly slot unless the preregistered holdout gate beats the current same-run best.

IR-H31-PROXY-01 · medium

H31 is a regularized worming-like proxy, not a full Poisson-wavelet inversion

Finding: The available RTP and isostatic-gravity grids are processed through a fixed Fourier 1/k-like scale-space proxy with taper, padding, thresholds, and nearest-maximum tracking. True magnetic field parameters, vendor filter formula, source distribution, remanence, depth, and fault geometry are not independently known.

Impact: Persistence is not proof of faulting, depth, geothermal activity, or discovery; artifacts and missed edges are possible.

Status

disclosed method limitation

Mitigation: Use only preregistered settings, name it a proxy, log diagnostics, and require spatial holdout plus fresh confirmation before considering a candidate.

IR-29-FOOTPRINT-DIFF · high

Feature and template footprints differ

Finding: training_features.tif (owner mirror, sha 4371c82e...) has 5,165,852 finite cells vs the sample_submission template's 5,167,373: 3,061 template-footprint cells are nodata inside the features, and 1,540 feature cells lie outside the template footprint. Any pipeline that assumes 'finite in features == finite in template' silently mis-scores/NaNs 3,061 scored pixels.

Impact: This is a carried-forward finding from the earlier main-branch H29 work; review the cited evidence or action before using affected data or interpretations.

Status

open

Mitigation: This repo: worming computes on the FEATURES mask; submission emission is masked to the TEMPLATE footprint and every in-footprint pixel is written finite (0.0/1.0), so the difference cannot produce NaN-inside-footprint. Upstream (competition data) needs owner confirmation that both rasters are authentic copies.

IR-29-LINE-PERSISTENCE-INVERSION · medium

Measured line-orientation persistence contradicted the naive artifact heuristic

Finding: The acquisition-line audit (knowledge/01 §2d) predicted E-W striking edges (flight-line aliasing, 200/400 m E-W lines) should be *less* persistent under continuation. Measured on the full grid: mean magnetic persistence by strike is E-W 0.656, Other 0.607, N-S 0.562 — E-W edges are, on average, the MOST persistent. The naive 'E-W = artifact' heuristic is therefore NOT usable as a filter on this grid; regional geology (E-W striking ranges in the Walker Lane transform corridor) plausibly dominates the aliasing signal.

Impact: This is a carried-forward finding from the earlier main-branch H29 work; review the cited evidence or action before using affected data or interpretations.

Status

open

Mitigation: The measured audit refutes a naive E–W suppression rule on this grid. H29-3 spectral-notch work remains a distinct registered research idea; no line-path data are used until officially sourced and validated.

IR-H29-GATE-RECONCILIATION · medium

H29 extra draws and original gate snapshot disagree

Finding: The preserved H29 raw holdout and run log contain draws 0–3 for every arm, although the preregistered screen draws 0–1 all fail. The original gate builder only populated draws 0–1 and then looked for confirmation draws 2–3 in that same mapping, so confirm_draw was always null. Treat draws 2–3 as exploratory extras, not eligible confirmations, because no arm passed the screen. The screen-based no-slot conclusion is unchanged.

Impact: Do not describe the extra draws as a valid confirmation stage or infer that the original null confirmation field was computed from them. All H29 metrics are catalogue-gap proxy results, not competition scores.

Status

documented; no effect on failed screen decision

Mitigation: Preserve the original raw cells and gate file; see knowledge/06_h29_gate_reconciliation_2026-10-03.md and evidence/h29_gate_reconciled.json. The gate helper now checks complete draws and only counts confirmation after screen pass; synthetic tests cover the edge cases.
